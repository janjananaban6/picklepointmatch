PICKLE POINT MATCH — OPEN PLAY SESSION IMPORT MERGE REPAIR
Build: ppm-session-import-merge-20261126-v1

WHAT WAS WRONG
- The CSV preview marked every Session ID already present in the dashboard as
  "Duplicate · skipped" and excluded that row from the POST request.
- The server also accepted linked matches only when the session was newly inserted
  in the same request. It therefore skipped linked matches for an existing session.
- Re-importing a partially restored session could not recover missing attendance
  or match records.

WHAT THIS REPAIR DOES
- Existing sessions owned by the signed-in organizer are eligible for a safe merge.
- New attendees are appended without replacing the current attendance roster.
- Manually removed attendees are not re-added by the import.
- Missing session metadata is filled only when its saved value is blank.
- Missing linked match records are added to an existing session.
- A match with the same Session ID + Match ID is not duplicated; blank fields in an
  existing match can be completed from the CSV without overwriting populated values.
- Repeated rows with the same Session ID in one CSV are combined.
- Sessions currently live, or sessions owned by another organizer, are rejected.
- Repeating the same import is idempotent for sessions, attendance and identified
  match records; it does not delete existing data.
- The import keeps using the existing authenticated endpoint and PostgreSQL storage.

DEPLOY SAFELY TO THE EXISTING RENDER SERVICE
1. Keep a private backup of the current source and database before deploying.
2. Use the SAME GitHub repository, branch, Render web service, and PostgreSQL database.
3. Do not create a new Render service or database, and do not change DATABASE_URL,
   SESSION_SECRET, or organizer credentials.
4. Confirm the Render web service Root Directory points at the project root containing
   package.json, package-lock.json, server.js, dashboard.html and dashboard.js.
5. Build Command: npm install --omit=dev
   Start Command: npm start
6. Deploy the existing service. After deployment, open /api/health on the same Render
   domain used by the organizer dashboard.

VERIFY THE DEPLOYED BUILD
The /api/health response must include:
  "build": "ppm-session-import-merge-20261126-v1"
  "capabilities": { "sessionImport": true }
  "sessionImportEndpoint": "/api/organizer-dashboard/sessions/import"
  "storage": "postgresql"

After the health response matches, hard-refresh the dashboard and try importing a CSV.
Existing sessions should show as "Merge" in the preview. The result summary reports
new sessions, merged existing sessions, added matches, and any invalid rows.
