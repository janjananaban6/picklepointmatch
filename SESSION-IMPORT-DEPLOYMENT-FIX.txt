WHAT CAUSED THE WARNING
The dashboard attempted POST /api/organizer-dashboard/sessions/import, but the live
Render backend returned HTTP 405. The dashboard then checked /api/health and found that
the running server did not advertise capabilities.sessionImport = true. This means the
currently deployed server.js is older than the dashboard files (or Render is deploying
a different service, branch, or Root Directory). It is not a CSV parsing error.

WHAT IS INCLUDED IN THIS REPAIR
- server.js contains the authenticated POST import route and advertises its capability
  from /api/health.
- dashboard.html and dashboard.js use a matching versioned cache token.
- The server and health endpoint use one shared path constant for the import route.
- The redundant unreachable startup statement was removed.
- The project archive has server.js, package.json, and render.yaml directly at its root.
- The archive excludes node_modules and local data/ records. Render installs dependencies;
  keep the original private ZIP as a backup if its local data/ records have not already
  been migrated to the existing PostgreSQL database.

DEPLOY TO THE EXISTING RENDER SERVICE — DO NOT CREATE A NEW ONE
1. Keep the original uploaded ZIP as a private backup. Do not publish its data/ folder or
   organizer account file to a public GitHub repository.
2. Back up the existing Render PostgreSQL database before deploying. Keep the current
   DATABASE_URL, SESSION_SECRET, and organizer credentials unchanged.
3. Put the contents of this repaired ZIP at the top level of the SAME GitHub repository
   and the SAME branch connected to the existing Render web service. The root must show
   package.json, package-lock.json, server.js, render.yaml, dashboard.html, dashboard.js,
   and the other app files together. Do not put these files one folder deeper.
4. In the existing Render web service, check Settings > Build & Deploy. Set Root Directory
   to blank (repository root), unless your existing repository intentionally uses a

5. Deploy the existing service from the same branch. Do not create a second web service,
   do not replace the existing PostgreSQL database, and do not change DATABASE_URL.
6. Wait for that deployment to finish successfully, then open /api/health on the same

The /api/health JSON must include all of these:

  "capabilities": { "sessionImport": true }
  "sessionImportEndpoint": "/api/organizer-dashboard/sessions/import"
